FRED RÉSUMÉ DE RÉFÉRENCE

Voici un résumé des commandes pour FRED et leurs adresses de ligne par défaut. "(.)» Signifie qu'une commande fonctionnera sur la ligne actuelle si aucune adresse est spécifiée. "(.,.)» Signifie qu'une commande fonctionnera sur la ligne actuelle si aucune adresse sont spécifiées, et sur la ligne adressée unique si une adresse est spécifiée.

Les commandes qui ne nécessitent pas un <nl> dans le cadre de leur format peut être placé un après l'autre sur la même ligne. De telles commandes peuvent être séparés par un ou plusieurs espaces; parfois sans espaces sont nécessaires.

Placement d'un élément entre crochets (par exemple "[article]") dans les formats ci-dessous signifie que l'élément est facultatif. Séparer les articles avec ou barres comme dans "item1 | item2 | item3" signifie que l'utilisateur a le choix de l'un des éléments donnés.

Commandes:

A) (.) Un <texte> Ajouter du texte après la ligne

  • le texte doit se terminer par \ F moins sur la même ligne que A et OI \ F en vigueur
  • "." mettre à la dernière ligne du texte tapé dans

C) (.,.) C <texte> Modifier les lignes

D) (.,.) D Supprimer les lignes
  • pas d'adresse enveloppante

E) E <patname> / <motif> / Nom motif
  • motifs récursifs autorisés

F) F Imprimer Faits

  • associés <filename> avec un tampon courant

        FB faits tampons d'impression
  • affiche le nom, ".", "$", le nom de fichier associé, le statut douteux de chaque tampon 
        FE faits Imprimer motif

        FF faits de fichiers tampons d'impression
  • imprime le nom et le nom de fichier associé pour chaque tampon

  • lorsque le registre a une base, imprime une commande N pour la base et un autre pour la valeur 
        FO option d'impression faits
  • imprime toutes les options actuellement activées 
        FV Version imprimable

  • une version de l'éditeur ne peut pas être utilisé après sa date d'expiration 
        F? Afficher les tampons douteux

Directives Stream

\ B <bufname>
Insère contenu du tampon <bufname> dans le flux d'entrée. Peut être utilisé de manière récursive.
\ C <char>
Causes <char> à prendre littéralement.
\ E <patname>
Représente motif précédemment associé à <patname> par une commande E. Seulement spécial à l'intérieur d'un motif.
\ L <bufname>
Semblable à \ B <bufname> sauf que tous les caractères <bufname> sont considérés comme étant précédé d'un \ C.
\ N <regname>
Place le contenu du registre de numéro <regname> dans le flux d'entrée, selon les commandes de format de registre applicables.
\ O <char>
Causes <char> pour prendre une signification spéciale, il peut avoir dans ce contexte, quels que soient les paramètres des options actuelles.
\ R
Prend une ligne d'entrée du terminal. Pas de directives de flux sur cette ligne sont efficaces. Le <nl> caractère à la fin de la ligne est ignoré.
\ S <bufname>
Semblable à \ L <bufname> sauf que tous les caractères <NL> dans <bufname> sont supprimés comme le tampon est placé dans le flux d'entrée. caractères spéciaux dans <bufname> sont pris à la lettre, sans leurs significations particulières.
\ W
Remplacé par le nom du fichier associé au tampon courant.

Fichier I / O

La commande W va créer des fichiers, il ne peut pas trouver. Si le nom de fichier spécifié est inférieur à neuf caractères et ne contient pas de "/" ou "$", un fichier temporaire est créé; sinon un fichier permanent est créé.

Des fichiers permanents sont retirés de l'AFT après chaque lecture réussie ou d'écrire; les fichiers temporaires ne sont pas supprimés de l'AFT.

Quand un fichier permanent est lu ou écrit sans une adresse de ligne spécifiée, le nom complet du fichier est associé avec le tampon courant. Le nom du fichier associé au tampon courant ne change pas si les adresses de ligne sont spécifiées. Si un fichier avec un mot de passe est lu ou écrit sans adresses de lignes spécifiées, FRED va associer le nom du fichier avec le tampon courant, mais dépouiller le mot de passe du fichier. Ainsi, l'utilisateur doit indiquer le mot de passe chaque fois que le fichier est lu ou écrit, puisque FRED ne se souviendra pas du mot de passe.

Si une erreur I / O se produit dans l'accès à un fichier, la commande Y peut être utilisée pour obtenir une explication des raisons pour lesquelles l'accès a échoué.

Patterns et Matcher Pattern

Caractères spéciaux:

^
Ce caractère correspond au caractère null commencent une ligne.
$
Ce caractère correspond au caractère nul avant la balise <nl> dans les lignes qui ont un <nl>. Dans les lignes sans <nl>, "$" correspond à la fin de la ligne physique.
.
Ce caractère correspond à tout caractère sauf <nl>.
+
La construction "<motif> +" correspond à toute séquence d'une ou plusieurs chaînes correspondant à <motif>.
*
La construction "<motif> *" correspond à toute séquence de zéro ou plusieurs chaînes correspondant à <motif>.
@
La construction "@ (<n>)" correspond à la chaîne null immédiatement avant le <n> e caractère d'une ligne. "@ (- <N>)" correspond à la chaîne vide immédiatement après la <n> e personnage de la fin d'une ligne. "@ (- 1)" correspond à la chaîne null immédiatement avant la balise <nl>. "@ (0)" correspond à la chaîne null immédiatement après la <nl>. "@ (<N> -)" correspond à la chaîne vide avant la balise <n> e caractère d'une ligne ou devant un caractère précédent dans la ligne. "@ (<N> +)" correspond à la chaîne null avant la balise <n> e caractère d'une ligne ou devant tout caractère suivant dans la ligne.
|
La construction <motif1> | <pattern2> correspond à toute chaîne qui correspond soit <motif1> ou <pattern2>.
()
N'importe quel motif peut être placé entre parenthèses pour obtenir un motif qui correspond à l'original.
[
"[<String>]" définit un modèle qui correspond à tout caractère dans <string>. "[^ <String>]" définit un modèle qui correspond à tout caractère PAS dans la chaîne.
{}
La construction {<motif>} <char> crée un motif dans lequel toute correspondance de chaîne <motif> est associé au nom <char>. <Char> peut être utilisé pour représenter la chaîne correspondante sur le côté droit de commandes S.
\ E
Voir la section sur les directives Stream.
#
Le "#" empêche le Matcher Motif de la sauvegarde et de faire une seconde tentative pour trouver une chaîne correspondant à un modèle donné.
//
Le motif null // correspond au modèle le plus récemment rencontré.
NUL
La chaîne vide (généralement écrite () pour le distinguer du motif vide //) correspond à tout caractère nul.

La construction <nombre> / <motif> / définit un quasi-modèle qui correspond au <numéro> ème occurrence de <motif> en ligne. La construction - <nombre> / <motif> / définit un quasi-modèle qui correspond au <numéro> ème occurrence de <motif> à partir de la fin d'une ligne. Quasi-modèles peuvent être utilisés à la place des modèles dans E, S, ZL, et les commandes ZU.

Adresses de ligne

Formes valides:

<Nombre>
numéro de ligne ordinaire.
$
Dernière ligne dans un tampon.
.
ligne actuelle dans le tampon.
+ <Nombre>
Comme première adresse, ce qui équivaut à ". + <Nombre>". En tant que deuxième adresse paire d'adresses, ce qui équivaut à la première adresse plus <numéro>. Si aucun <numéro>, équivalent à "+. 1".
- <Numéro>
Comme première adresse, équivalent à ".- <nombre>". En tant que deuxième adresse dans l'adresse paire, ce qui équivaut à la première, moins d'adresse <numéro>. Si aucun <numéro>, équivalent à ".-1".
/ <Motif> /
Première ligne après "." contenant <motif>. Rechercher <motif> commence à la ligne après ".", Enroule autour en haut de la mémoire tampon, si nécessaire, se termine à "." si <motif> introuvable.
~ / <Motif> /
Première ligne après "." qui ne contient pas <motif>.
- / <Motif> /
Première ligne avant "." contenant <motif>. Rechercher <motif> commence à la ligne avant ".", Enroule autour de la fin du tampon, si nécessaire, se termine à "." si <motif> introuvable.
- ~ / <Motif> /
Première ligne avant "." qui ne contient pas <motif>.
<Addr>
Symbole utilisé pour les adresses valides ci-dessus ou à l'adresse ci-dessous construit.
<Addr> + <nombre>
Fait référence au <numéro> ème ligne après <addr>.
<Addr> <nombre>
Identique à <addr> + <nombre>.
<Addr> - <numéro>
Fait référence au <numéro> ème ligne avant <addr>.
<Addr>.
Fait référence à <addr> +1.
<Addr> + / <motif> /
Fait référence à la première ligne après <addr> contenant <motif>. Rechercher <motif> commence à <addr> +1, enroule autour de la partie supérieure du tampon, si nécessaire, et se termine à <addr> si <motif> est introuvable.
<Addr> / <motif> /
Identique à <addr> + / <motif> /.
<Addr> ~ / <motif> /
Fait référence à la première ligne après <addr> ne contenant pas <motif>.
<Addr> - / <motif> /
Fait référence à la première ligne avant <addr> contenant <motif>. Rechercher <motif> commence à <addr> -1, enroule autour du fond de la mémoire tampon, si nécessaire, et se termine à <addr> si <motif> est introuvable.
<Addr> - ~ / <motif> /
Fait référence à la première ligne avant <addr> ne contenant pas <motif>.
^
Raccourci pour ".-1".
<Addr> ^
Raccourci pour "<addr> -1".
*
Raccourci pour "1, $".
<Addr> *
Raccourci pour "<addr>, $".
&
Raccourci pour ". + 1,. + <Pagesize>" où <pagesize> est réglé par la commande O + P. Si aucun <pagesize> a été défini, et va générer ". + 1,. + 20".
<Addr> &
Cela génère la paire d'adresses "<addr>, <addr> + <pagesize>".
<Addr> - &
Cela génère l'adresse unique <addr> - <pagesize>.

Programmes tampons

Un programme est appelé par la ligne de commande, "fred filename arg1 arg2 ..." où le nom de fichier est le nom du fichier contenant le programme. Si le nom de fichier ne se trouve pas dans le catalogue actuel, le bootstrap FRED cherche sous "/ fred / filename" puis "fred / filename".

Les arguments "arg1", "arg2", etc. (le cas échéant) sont placés sur des lignes séparées dans un tampon "0". Le fichier spécifié est lu dans le tampon ".". La date est placée dans le tampon "d" dans le format numérique "mm / jj / aa". Le temps est placé dans le tampon "t" dans le format numérique "hh: mm". Le userid courant est placé dans un tampon "u". S'il y a un fichier init nommé "/fred/.init", FRED exécutera les inits avant d'exécuter les commandes qu'il avait lu dans le tampon ".".

Limitations de la langue et considérations particulières

Lors de la lecture d'un fichier, FRED ne sera pas accepter un record de plus de 2000 caractères. Lignes de plus de 2000 caractères sont divisés en lignes distinctes de 2000 caractères chacune. Une commande S ne peut pas allonger une ligne au-delà de 2000 caractères.

FRED utilise le caractère octal \ 777 comme un caractère interne spécial; Pour cette raison, le caractère ne peut pas apparaître dans le texte d'entrée.

Si les lignes nulles sont fournis pour remplir une construction \ R, et sauts de ligne sont utilisés plutôt que des retours chariot, tous les autres aliments de ligne est ignoré.
